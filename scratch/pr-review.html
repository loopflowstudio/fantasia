1. Review placement and price before renting

Observed locally at d8307606; default checked-in mix and direct-self-play recipe. No provider request.

$ uv run manabot remote compile --regime experiments/regimes/direct-self-play.json --mix ops/mixes/runpod-small.json --seed 197 --out .runs/pr-review-plan.json
Plan: .runs/pr-review-plan.json; projected ceiling $0.310, including reserves

The mix allows six vCPUs, one worker and at most four threads. Its $0.60/hour ceiling plus $0.02 storage allowance over 30 minutes produces the displayed estimate. This is declared-price arithmetic, not a quote or billing guarantee.

Implementation choice: the compiler supports ordinary, self-contained self-play only. A supervised or belief stage is rejected before rental. The accepted hardware direction is broader; distributed placement and larger models remain separate work.

Deployment requires the exact committed source to be publicly fetchable. Each command uses a fresh directory, stores intent before create, and records provider identifiers only in private evidence. Receipt owns deployment state; the existing TrainingRun and VerifyStore retain training authority.

The probe is repeated on every run and consumes setup time. During training the terminal has no live progress stream; the receipt’s phase is saved locally. A provider outage or a container that never starts can leave cleanup unresolved.

CUDA wiring and the independent pod guardian

Compared with the base, Execution now admits CUDA. The executor moves Agent before optimizer construction, passes device to collector and Experiment, synchronizes charged phase boundaries and preserves CUDA RNG around export admission. CPU remains the default. These changes have not yet been exercised on a real GPU in this implementation.

3. Return immutable evidence and load the policy

After training, the remote command packages the closed output tree and downloads its manifest and files. Producer paths remain unchanged in TrainingRun; the bundle maps them to verified local files. A failed training status or mismatched database prevents successful deployment.

Consequential acceptance gap: a successful remote run proves loader admission, not a completed game. The separate tests.remote.live_acceptance helper requires actual CUDA optimizer exposures and evaluates one four-leg arena block through the existing monitor evaluator. That helper has not run; a loader-only success cannot satisfy the Task.

The receipt, failed attempt and any downloaded files survive. Cleanup does not retry training or complete an interrupted transfer; another deployment needs a fresh output directory. Confirmed absence and known cost are distinct: the acceptance helper refuses another rental when prior cost is unknown.
