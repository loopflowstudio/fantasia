01 / Run once; keep the failed attempt

Before this PR, the checks lived in individual tests. The new CLI creates a fresh evidence directory, supervises a worker, and returns a report path plus an exit status. A timed-out attempt survives for inspection; continuing means choosing a new directory.

The parent owns elapsed time and termination; the worker checkpoints evidence after each seed. result.json is authoritative, while report.md is its readable projection. Each file is replaced atomically; the pair is not a single transaction.

Evidence ownership and explicit states

02 / Fit three policies, then ask many questions

The extracted fixture now returns a named decision with preference, split, native status and resolved outcomes. Existing structural tests and the nightly runner share this owner. One policy per seed sees all six families; held-out cases never enter its loss.

Low/high public life selects opposite artificial preferences. “Held out” means nearby life totals and different native shuffle seeds, not unfamiliar strategies. Fit uses variants 0/2; held-out uses 1/3. Ability rows are synthetic projections; their native legality is checked separately in Rust.

The capacity checkpoint deliberately spans multiple setups. It carries source/world/config/case identity but is not a playable match-bound checkpoint. The production PPO layer below owns that different reload contract.

Frozen limits and curriculum expansion

03 / A green family cannot hide a bad case

Every preferred choice must reach probability ≥ .90, survive offer/object reordering, and become a tied candidate pair when its identity channel is removed. The Markdown table groups by seed, family and split, displaying minimum probability and requiring every row to pass.

Here no_update is exactly the stored initialization probability. The identity-removed control is evaluated on the trained policy. Neither is a separately trained model. Reordering is invariance evidence; the case split supplies the distinct held-out evidence.

The explicit --pr CLI option omits PPO and records a skip, but the actual GitHub PR workflow invokes the full command. “Passed” must therefore be read with the config and skips, especially for manually produced reports.

04 / Learning now has a reload-and-control contract

The existing passive-opponent PPO test is extracted into run_positive_control(tmp_path, *, deadline) → PPOResult. Both the test and nightly runner call it. The production collector and update remain; evaluation now follows ordinary checkpoint reload and compares against an unchanged policy on the same held-out deal seed.

The extra policy supports the reward-driven learning claim: 64 updates × 8 environments × 128 transitions, terminal rewards, no alternate PPO loss. It proves improvement against a frozen passing opponent in the Mountain/Gray Ogre toy world; it does not establish general playing strength or MTG-118 completion.

05 / Artifacts are automatic; public delivery is not

The workflow adds nightly, relevant-PR and manual execution with overlap protection, a 15-minute job timeout and 30-day artifacts. Discord is a separate local API: a completed Result plus an evidence URL produces either a confirmed message receipt, a duplicate no-op, or a pending receipt that blocks retry.

Remaining product boundary: a webhook, public evidence hosting and the mini-side publication scheduler are not provisioned. payload() checks HTTPS syntax, not public accessibility; a private or nonexistent HTTPS URL is accepted. A successful webhook response alone would not prove the report is public.

The key is Keychain service name + UTC run-start date. Once a failed report is sent, a corrected run for the same service/day returns “already posted.” Pending delivery has no automated reconcile command: inspect Discord and reconcile the local receipt before retrying. This favors avoiding duplicates over automatic recovery.

Scheduling and retained failure visibility

The preflight fallback makes a report when setup fails before the CLI starts. The eight-minute watchdog covers the diagnostic worker; an external cancellation or whole-job timeout can still prevent final summary/upload steps from running.
