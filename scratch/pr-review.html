How to read this review

Stops 1–5 explain the training behavior. Stops 6–8 explain what the experiments can establish and how failures behave. Stop 9 covers maintainability. Amber prompts identify choices for feedback, not changes already approved or applied.

01 / A recipe becomes a bounded, recorded run

The accepted goal is to make training alternatives easy to compare. A TrainingRegime holds ordered stages; a TrainingRun records one seeded execution. A study combines planned runs, an evaluation protocol, and offline reports. There is no additional general-purpose Experiment database model.

The delivered API is intentionally bounded: three stage operations, a shared architecture per regime, and CPU/float32 execution. It does not yet express training a belief model after freezing a policy.

Concrete caller journey: the scientific CLI validates a frozen plan, then executes each seeded recipe. In the direct-RL arm, policy-0 collects fresh experience, updates weights, and exports a checkpoint. policy-1 continues the live collector and Adam state. The eventual report selects only checkpoints available at each measured cost.

For technical feedback

Does a regime-wide architecture and same-operation continuation cover the next experiments? RL → frozen belief training → search currently needs new stage operations and artifact contracts.

02 / Long games become learner-decision transitions

Self-play uses the current learner on both seats. The collector stores designated learner decisions, with alternating learner seats across streams; opponent steps advance the environment without becoming that stream’s training rows. Four streams collect 256 learner transitions each per update.

The shared attention model has hidden width 64 and four heads, semantic cards for Allies/Lessons, and no belief input in these plans. Both arms use that architecture; RL trains policy and value, while distillation trains policy only.

Discounting is γ = 1. Separate GAE passes can give the policy and critic different trace lengths. A terminal flag stops the recurrence; a nonterminal batch boundary bootstraps from the critic. Even λ = 1 here is not necessarily a full-game Monte Carlo return.

For technical feedback

Policy λ remains 0.95 in every core arm: its trace decays across learner decisions, even with γ = 1. Is the critic-only λ change the horizon intervention intended for this first screen? Compound decisions are not grouped into a new joint action here.

03 / The update is PPO with explicit regularization

This implementation uses a PPO-style clipped objective with coordinated regularization. Ataraxos itself uses importance-ratio clipping and a KL penalty to the collection policy; those features are not departures from the paper. Its damping coordinates regularization strength and update size. See the Methods: Dynamically damped self-play. The current manabot implementation has four optimizer epochs and four minibatches; full fidelity still requires checking estimators, filtering, normalization, schedules and update organization against the supplement. The policy objective is combined with critic regression and two forward KL penalties: new policy ‖ reference, and new policy ‖ collection policy.

With a uniform legal-offer reference, the reference KL has the same parameter gradient as a negative entropy bonus for a fixed observation. A separate action-type-uniform option exists, but none of the core frozen arms uses it. That distinction matters when one action family has many more legal offers.

For technical feedback

The current experiment measures selected controls in our existing PPO-style trainer. Clipping and KL alone neither distinguish it from Ataraxos nor establish full fidelity. Paper-faithful implementation and the equation-by-equation paper/supplement comparison are explicitly tracked in ETU-92. The full lesson coverage map connects the remaining mechanisms to their Tasks.

04 / Filtering changes both the actor and the critic

The filter keeps the largest absolute advantages by batch rank, then applies a minimum magnitude. It is not merely a fixed threshold. Advantages are normalized using the retained subset. The same selected indices feed every loss, including value regression and both KL penalties.

The critic consequence is visible in the preceding objective: returns[indices] uses that same filtered minibatch. Low-advantage decisions disappear from critic training as well as policy training. A high minimum can remove every row; the implementation records a skipped update and does not step Adam.

For technical feedback

Should the value head learn from all rows while only policy updates are filtered? This is a substantive algorithm choice, especially because the critic supplies the next batch’s advantages. The current five-arm study conflates both effects under “advantage filtering.”

05 / Search teaches a fixed policy target

The teacher arm collects visit distributions from uniform-prior determinized PUCT, then fits the policy on accumulated shards. Later stages continue weights and Adam state. They do not feed the newly trained policy back into the teacher. This compares fixed-search distillation with direct self-play RL, rather than an AlphaZero-style improving search teacher.

Each of four collection rounds has 161 games. The direct arm has four stages of 1,789 updates. These counts came from timing calibration; the comparison charges teacher collection as well as optimization. The validation split uses whole game IDs divisible by ten.

For technical feedback

Is this the right “search-as-teacher” baseline for the immediate decision? It tests the existing fixed teacher’s learning curve, not the ceiling of search combined with a progressively stronger policy/value network.

For technical feedback

Should a later study include policy trace length, structured reference, collection KL, or averaged-policy behavior? EMA support currently exports an evaluation-only model; it neither collects experience nor participates in the core raw-only arena. The screen is a selected ablation, not a comprehensive test of Ataraxos.

07 / The report compares weights that actually existed at each cost

Development and untouched endpoint deals are disjoint. Every deal has four seat/deck legs, stochastic policy inference, and random, scripted-greedy, and PUCT-64 anchors. Learning-speed endpoints cover all nine cross-seed pairs; the ablation uses matched seeds.

The report uses the last measured checkpoint available at a cost. It does not interpolate future strength backward. When observed cost ranges do not overlap, the comparison is unavailable. This occurred in calibration and is an informative boundary, not a tie.

Ablation development has two paired/anchor deal blocks; endpoints have four. Learning-speed development has twelve; endpoints have 96 paired and 24 anchor blocks. Three training seeds provide exploratory descriptive uncertainty, not a robustness or exploitability certificate. Invalid, truncated, or unreplayed games cannot become scored draws.

For technical feedback

Are these fixed anchors and endpoint matchups sufficient to decide the next training investment? The small ablation endpoints can screen for large effects, but close differences need more evidence. No trained exploiter is part of this protocol.

08 / An exported file must load before it is admitted

After optimization, export writes a temporary checkpoint, renames it, and loads it through the ordinary checkpoint player. If admission fails, the candidate is recorded as rejected; it is not silently promoted. The run records failures and accumulated cost before raising the error.

Live collector continuation works between stages in one process. Saving optimizer weights is not a complete process-resume implementation. Study --resume is for evaluation after every frozen training run has completed.

For technical feedback

Before larger campaigns, should recovery preserve partial training progress, RNG state, collector state, and schedule time? That is separate from the scientific comparison and should preserve the identity and cost of every attempt.

09 / Make the next algorithm review easier

Jack requested fully typed Python, more useful comments, and organization that emphasizes key data structures and APIs. The AGENTS.md guidance, landed in PR #204, adopts those conventions after comparison with Loopflow’s guide.

The source above shows specific cleanup opportunities: the central objective and GAE functions lack parameter/return annotations; analysis passes nested untyped records; and optimizer behavior is packed into one routine. Prefer named batch/diagnostic/result types, documented tensor dimensions and ownership, and short sections that separate estimator construction, selection, objective evaluation, and updates. Preserve the numerical behavior with focused checks when implementing that cleanup.

This review changes no training code. The conventions are a landed documentation change. They do not imply the existing code is fully typed, or that a configured type checker has passed.

For technical feedback

Feedback can refer to a numbered stop: desired behavior, the current choice to change, and the experiment that would distinguish alternatives. Algorithm changes should become a versioned plan or new run rather than silently changing the active cohort.
