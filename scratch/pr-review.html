1. Declare a larger model

The base limited depth to 1 or 2. The new fields accept positive depth and expansion; the existing compound-model depth restriction remains. Unset expansion stays absent from serialization.

Omitting feedforward_dim preserves a baseline’s explicit expansion; passing None resets it to heads × width. A width-64 variant of an explicit 1536-wide baseline therefore keeps 1536 unless reset. This is an intentional recipe distinction callers need to understand.

Decisions and evidence limits

Operational mismatch to consider: caught child failures set scale.json.status = "failed", but the CLI discards the returned report and returns normally. For example, unavailable MPS produces a retained failed child while the shell can still receive exit status zero. Automation must inspect the report. Whether the CLI should also return nonzero remains a review question; no product code was changed here.

Padding finding: the measured input is two players + 120 cards + 80 permanents + one value token. Actions and events are not extra attention rows. Trimming padding requires index remapping and preservation of historical pooling contributions; naive trimming changes the model. No packing was delivered.

Scope: the opt-in ladder preserves ETU-103’s cohort. ETU-107’s decoder/policy-scoring work and ETU-114’s stage-device execution remain separate. The retained 208.09-second attempt and recovery establish bounded software feasibility; they do not establish useful learning, complete-game improvement or chapter acceptance.

Review status: source and retained logs inspected, prior test results attributed above. No new benchmark, scientific cohort, approval or merge decision. The next useful action is Jack Heart’s review of this implementation and the CLI failure-reporting question.
