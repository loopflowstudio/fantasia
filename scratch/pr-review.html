1. One command starts a recorded attempt

Jack Heart’s accepted goal is to vary ordered training recipes without rebuilding orchestration. A caller supplies a recipe, seed and fresh output directory. The new CLI path validates JSON and creates the SQLite owner beside that directory. Mixing a recipe with preset overrides fails before execution; ordinary preset training still takes its existing path.

Example invocation: uv run manabot train --regime experiments/regimes/direct-self-play.json --seed 197 --out .runs/review-example. This is illustrative; this review did not launch it.

The executor creates a unique run, records the resolved recipe digest and named seed streams, then changes stage state as work proceeds. The visible result is checkpoint files plus run.json; SQLite remains the status authority.

2. A later stage can consume only compatible earlier work

Collection, supervised fitting and self-play are the three implemented operations. Dataset names must refer backward to collections; continuation must name an earlier stage of the same kind. Self-play has only one live collector to continue, so branching from an older collector is rejected. Architecture and match are shared across the recipe; external artifacts and multiple named models from the original design are not implemented.

Local refinement shown below; not yet in PR #200

The published implementation already rejects those reference categories; the local refinement keeps stage objects and the latest collector directly. Before consuming an output, the executor rehashes its bytes. “Immutable” here means a unique run directory and digest-checked artifacts, not filesystem write protection.

3. A second fitting round keeps what the first learned

Trace a cumulative teacher recipe: the collection stage produces complete-game shards with run-local game IDs. Fitting consumes named shards; IDs divisible by ten remain validation games even when more data arrives. The next fitting stage receives both learner weights and Adam state. This prevents a fresh validation split or optimizer reset from masquerading as continued training.

The existing supervised trainer gains two important branches: restoring Adam still honors the new stage’s declared learning rate, and explicit whole-game partitions must both contain data. Existing callers that omit the new arguments retain the previous split behavior.

How self-play continuation differs

Self-play retains the live trainer, collector and EMA clock within this process. The local cleanup removes redundant optimizer snapshots and closes experiments through ExitStack. A saved model is still not an exact process-resume file.

4. A saved checkpoint must reload before it is admitted

After fitting, the ordinary checkpoint writer saves temporary bytes. The executor renames the file, hashes it, and invokes the ordinary loader. A rejected checkpoint remains on disk with a rejected-artifact record; it is not advertised as an admitted raw output. Successful completion selects the last raw output, without comparing playing scores.

Run and stage updates share one SQLite transaction. JSON export reads that canonical record back. The base already had VerifyStore and checkpoint writers/loaders; this diff adds execution records and admission around them.

5. An interrupted attempt stays visible

A stage receives the earlier of its own deadline and the total run deadline. Resource checks sample process-tree RSS; they do not impose an OS memory ceiling. Teacher collection and fitting also check deadlines internally. A timeout or keyboard interrupt marks the attempt interrupted; other exceptions mark it failed. Costs and already recorded artifacts are retained before the error returns to the caller.

A teacher game that reaches a step limit is retained as evidence but rejected as training input unless it has an authoritative terminal outcome. Truncation cannot silently become a draw.

Local checkpoint-cost addition; not yet published

Per-phase timings already exist. The local change freezes each completed stage’s elapsed cost from run start, including earlier persistence overhead. The next checkpoint pays for intervening persistence; an earlier checkpoint’s cost never grows retroactively. ETU-91 still needs to consume this field.

Unfinished and older records leave cumulative_seconds null. These are cooperative budgets: a long operation between checks can overshoot before interruption is recorded.

6. Checkpoint integration remains unfinished

ETU-75 is a required acceptance dependency. This checkout has no manabot/model/world.py. Current validation only compares the regime’s world label with the native runtime and rejects unsupported belief inputs. This is narrower than ETU-75’s promised world/setup and semantic-input binding.

The checkpoint call shown here does not pass actual deck/sideboard player_configs. Integration must use ETU-75’s ordinary writer/loader contract, configure the selected semantic pack, and propagate semantic_cards and known_hand. Existing smoke reloads cannot certify those future tensors.

ETU-90 still owns complete EMA state handling. The current loop interpolates parameters only. Its supplied helper copies buffers as well, and is not integrated at this head. Raw learner weights remain the collection policy; EMA is a separately named evaluation output.

The published diff preserves the initial RL collector/native pause changes and study recipes/runners from before the ownership split. ETU-90’s final correctness evidence and ETU-91’s final replayed studies remain separate deliverables. Their reported child checkpoints are not part of this PR’s head.
