1. Finish leaves the consequences readable

In the authored combat fixture, damage and deaths have already committed when their narration appears. Click Finish: the floating beat disappears, but Recent consequences still names the damage, deaths and new turn. This is a fixture scenario, not a recording of the reported confusion.

The existing button moves the narration cursor to the end. It never clears the event array. The new history reads the latest 12 events directly, independently of that cursor.

The existing stage renders only while a current event exists; that is why Finish removes the overlay. History is mounted separately in both routes. The list includes committed events whose narration has not played yet; it is a view of current consequences, not a reconstruction of earlier board positions.

2. Pause holds the beat as new updates arrive

The new Pause narration button toggles playback. The existing timer effect cancels its timer while paused. A later live batch appends events but starts playback only if there was no current event, so a paused beat stays paused. The authoritative board can continue changing.

Boundary: recovery or a replay seek replaces the sequence and starts it from its first event; pause is not a persistent preference across recovery. The existing replay timer waits for the current event to disappear, so pausing narration also holds automatic replay advancement.

3. Reduced motion preserves reading time

Before this change, enabling reduced motion forced each beat to 100 ms. Now its reading duration follows the event’s suggested time, with explicit Fast-forward still dividing it by four. The existing motion class remains conditional on the accessibility preference.

The movement condition is shown in stop 1. This removes a timing override; it does not establish that every authored duration is comfortable to read. Pause and the retained list provide additional control.

4. The current prompt names who can act next

For example, choosing a Bolt target during the opponent’s turn still says “Your decision.” The status compares the authoritative prompt actor with the viewer’s player index, independently of active turn or the narration cursor. A watcher sees “Pilot’s decision.”

The earlier guards take precedence: Study, game over, connection loss and a pending action do not invite another live decision. This status describes the existing Command authority; it does not grant permission or alter legal offers.

5. What the evidence supports—and what remains open

Accepted intent: make consequences and the next decision legible through the existing semantic presentation path. Implementation choice: a 12-row readable window, pause control and separate current-decision text. The engine’s event projection, Command authority and replay storage are existing dependencies.

The display window is bounded to 12; the underlying player still retains its full event array until reset. Seeking replay replaces history with that position’s events. Missing events show an explicit empty state rather than inferred board-diff narration.

Inspected tests: pause survives an appended batch; Finish retains semantic rows; prompt actor is independent of active turn. These tests explain intended behavior, not observed human comprehension.
