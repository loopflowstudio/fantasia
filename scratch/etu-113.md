# ETU-113 — Experiment execution and editable comparison notebook

## Accepted direction — 2026-10-06

Jack Heart released the public-interface hold through launch-plan: implement the
coherent end-to-end core here, then PR/checks/landing. Experiment is declarative;
resolve remains pure; a shared explicit runner and execution record own actual
work. History and depth have their own readable Python declarations and thin
entry points. No competing campaign interface or worker. Interpretation, ledger
updates and next experiments belong to an experiment skill, not the software.

## Implementation

`Experiment.schedule` carries explicit seeds, order, configured hardware, wall and
additive process budgets, periodic export cadence and monitoring protocol.
`run_experiment` admits an explicitly configured local CPU host, runs one learner
plus one evaluator, persists ExperimentRun in VerifyStore, enables existing
periodic exports and consumes completed stage artifacts while later jobs train.
Foreign hosts/unsupported backends fail; no provisioning or silent fallback.
TrainingRun owns learning, reload, cost and optional recovery snapshots.

The reusable checkpoint queue pins run/artifact/coordinate/protocol bindings,
retains failed/interrupted jobs without retries, and exports existing dashboards.
Its lease spans worktrees and survives the parent's death in the worker. Process
sessions and watchdogs stop descendants. Resume continues pending cells with the
same allocation; explicit selected recovery uses the existing TrainingRun owner.
Original records and conservative orphan costs remain. Science deals stay reserved;
monitoring never changes counts, seeds, endpoints or selection.

One create-once `comparison.ipynb` loads all regime metrics, milestone rates and
uncertainty, compatible common-cost comparisons, costs/resources/failures and
source evidence hashes. All data-loading/plotting cells are editable. Run All
reads only; refresh preserves edits. Tracker projections are optional. No code
writes interpretations or repository knowledge.

History/depth consumers validate their existing calibrated ResolvedStudy, retain
all recipe digests and seed order, and reserve scientific deals. Monitoring must
fit their existing training envelope. They do not replace historical live launch
code or silently run endpoint science. The tiny demo exercises the same public API.

Delete — do not maintain: the first per-study launch-option draft was removed.
Historical campaign scripts remain for frozen evidence; new scheduling lives only
in the shared runner. No new cohort schema or model/training backend.

completed 16 replayed games in 50.78 execution seconds; evaluator time was 47.17 s
and additive learner/evaluator time 61.30 s. The notebook executed 35 plots,
retained edits, and resume did not retrain or re-evaluate. Earlier process/game
timeouts remain in `.runs/etu113-validation`; no failed evidence was replaced.
The notebook and 13 exact-byte source exports are packaged under
`experiments/study/experiment-demo`, with a checksum manifest and evidence note.

The accepted design/launch boundaries live in docs/experiment-execution.md.
